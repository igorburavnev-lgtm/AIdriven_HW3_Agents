## 3. Какие ошибки и проблемы возникали

### 3.1 Проблемы окружения (общие для обоих прогонов)

| Проблема | Проявление | Как решено |
|---|---|---|
| **Нет `git`** | `where git` пуст, `git init` невозможен на шаге П1 | Скачан PortableGit 2.56.0 в скрытую папку `.tmp/git` внутри копии и использован локально; в git не коммитится |
| **`pip install` заблокирован песочницей** | `OSError: [Errno 13] Permission denied` на распаковке колёс — даже для `six`; при этом сеть работает | Зависимости поставлены распаковкой тех же колёс PyPI в `.venv`. Версии сверены импортом: Django 5.2.18, DRF 3.16.1, celery 5.5.3, redis 6.4.0, plotly 6.9.0 |
| **Пакеты Tinkoff удалены с PyPI** | `/pypi/tinkoff-investments/json` → 404 при работающем `/pypi/plotly/json` | Оба прогона независимо пришли к одному решению: убрать из runtime-зависимостей, вынести в `requirements-tinkoff.txt`, сделать импорт ленивым |
| **Нет PostgreSQL / Redis** | `migrate` и Celery нельзя проверить вживую | SQLite по умолчанию; ограничение зафиксировано в обоих `MODERNIZATION.md` |

## 5. Как проверялись результаты

Проверялось не по отчётам агентов, а воспроизведением:

1. **Запуск кода:** `manage.py check` (0 проблем), `manage.py test` (**33 теста, OK** в каждом прогоне),
   `makemigrations --check` (`No changes detected`).
2. **Живой сервер:** `runserver` + 6 HTTP-проверок в каждом прогоне — `/`, `/api/v1/shares/`,
   `/user/login/` (с проверкой наличия `<input>`), `/admin/`, несуществующий `pk` (404),
   `/api/v1/portfolios/` анонимно (403). Результат: **6/6 в обоих**.
3. **Сверка заявленных чисел скриптом:** 56 требований / 42 дефекта / 9 неоднозначностей в
   `REQUIREMENTS.md` (DeepSeek) и 29 требований FR-P (Cursor) — совпало с текстами документов;
   в `MODERNIZATION.md` DeepSeek 31 DEF-ID, ни одного «висящего».
4. **Проверка ссылок на код:** разбор всех `файл:строка` и проверка попадания в существующие строки
   (337 ссылок в `REQUIREMENTS.md` DeepSeek, 119 в добавленном `REQUIREMENTS.md` Cursor — 0 выходов
   за границы файлов), плюс выборочная проверка смыслового соответствия (10 ссылок в каждом прогоне).
5. **Восстановление диффа:** построчное сравнение копий с нетронутым корневым проектом (61 файл) —
   получены реальные объёмы изменений: DeepSeek 19 изменённых + 14 добавленных, +3329/−195;
   Cursor 19 изменённых + 13 добавленных, +2241/−195.
6. **Ручная проверка «спорных» мест:** например, воспроизведение падений из `MODERNIZATION.md` Cursor
   и проверка, что после правок те же команды проходят.

## 6. Сколько времени и итераций заняло

Оценка по временным меткам ходов (приблизительно, время одного сеанса) и объёму изменений.

| Этап | Итераций (ходов) | Время, мин | Объём |
|---|---|---|---|
| П1 — копирование и проверка копий | 1 | ~9 | 2 копии × 61 файл, сверка SHA256 |
| П2 — DeepSeek, задания №1–2 | 1 | ~10 | 1958 → часть: `ANALYSIS.md` 733 + `REQUIREMENTS.md` 520 строк |
| П3 — DeepSeek, задания №3–4 | 1 | ~21 | 19 изменённых файлов, +3329/−195, 33 теста, коммит `525bb84` |
| П4 — Cursor, задания №3–4 | 1 | ~11 | 19 изменённых файлов, +2241/−195, 33 теста, коммит `d14adff` |
| П5 — повторный запрос Cursor | 1 | ~2 | Изменений нет (проверка состояния) |
| П6 — ревью, сравнение, отчёты | 1 | ~30 | 2 исправления (`a5508f2`, `a6038d5`), 4 документа в корне |
| **Итого** | **6** | **≈83** | 2 коммита + 2 коммита-исправления |

**Наблюдения по итеративности:**

- DeepSeek: задания №1–2 и №3–4 — по одному проходу, без возвратов «переделай»; единственная правка
  потребовалась уже на этапе ревью.
- Cursor: задания №3–4 — один проход; повторный (дублирующий) промпт не вызвал переделки, что
  сэкономило примерно полный цикл работы.
- Оба прогона потребовали одинакового числа исправлений по итогам ревью — по одному коммиту.

## 7. Вывод

Оба агента самостоятельно довели проект от нерабочего состояния (пустой `SECRET_KEY`, жёстко
прописанный PostgreSQL, отсутствующий SDK) до приложения с 33 зелёными тестами и работающим портфелем,
не задавая уточняющих вопросов по существу задачи. Различие — в форме отчётности: DeepSeek даёт
максимально трассируемую документацию (1958 строк, сквозные ID), Cursor — компактный воспроизводимый
инженерный журнал (1033 строки, цепочки «гипотеза → ошибка → исправление»). Подробное сопоставление —
в `COMPARISON.md`.
